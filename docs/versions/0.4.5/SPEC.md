# Saki 0.4.5 Claude Code hook 支持规格

> 状态：实施中；空闲会话显示筛选已实现，完整版本验收待完成。
> 更新：2026-09-16
> [工程设计](./IMPLEMENTATION.md) · [任务清单](./TASKS.md) · [用户指南草案](./USER_GUIDE.md)

## 1. 目标与基线

让 macOS 用户安装 Claude Code hook 后，通过现有 Saki Host 在设备上看到会话状态，
并与 Codex 会话同时工作。0.4.5 聚焦接入可靠性、生命周期边界、安装排障和完整验收。

当前工作区的 0.4.0-dev 已有 Claude Code adapter、来源隔离、hook 安装器及单会话真实
API probe；这些属于复用基线，不在本版重新实现，也不代表 0.4.5 已完成。
历史结果见 [0.4 TASKS](../0.4.0/TASKS.md)。0.4 的多 Session、最新提交主屏、容量、TTL、
恢复和传输契约继续适用；其未完成的真机验收不能因新建版本规划而视为通过。

## 2. 支持范围

- macOS 本机 Claude Code CLI 的用户主会话；可单独启用，也可与 Codex 共用 Host。
- 复用 `claude_code` 来源标识、HMAC 身份和本地 run；两个产品原生 ID 相同也不能串会话。
- 复用 `hooks install/check/uninstall --source claude_code`，支持用户级及显式项目级配置。
- 不增加线协议字段、设备状态或页面；继续使用 0.4 的 v1 能力协商与完整集合。
- 不包括远程/云会话采集、subagent 树、自动批准、SDK 专用集成、Wi-Fi 或视觉主题。

## 3. 事件映射与限制

以下为 Saki 的显示契约，沿用 0.4 基线。输入事件依据
[Claude Code 官方 hooks reference](https://code.claude.com/docs/en/hooks)
核对（2026-09-16）；实施时仍须记录实际受测客户端版本。

| 事件 | Saki 行为 |
| --- | --- |
| SessionStart | 新会话登记 idle，未开始任务时不占屏；resume 保留现有轮次和状态 |
| UserPromptSubmit | 新轮 starting、计时归零，成为最新提交主项 |
| PreToolUse | working；白名单交互提问工具显示 waiting_user |
| PermissionRequest | waiting_approval；批准仍在 Claude Code 完成 |
| PostToolUse | thinking，清除本轮等待 |
| PostToolUseFailure | thinking，显示固定工具失败摘要，不终结整轮 |
| Stop | completed，表示本轮回复结束 |
| StopFailure | failed，表示本轮异常结束 |
| SessionEnd | 冻结并保留最后状态，按既有 60 秒 TTL 清理 |

Notification 不触发批准状态，避免迟到通知恢复已经解除的等待；未知事件忽略。
SubagentStart/Stop 和明确带父身份的事件不创建独立用户任务。其他事件（例如 MCP
Elicitation）不纳入本版保证范围，未覆盖的输入等待须在指南中明确。

Stop 后若来源继续同轮工具活动，允许恢复活动状态。缺少原生轮次/因果元数据时，
不承诺完全消除跨轮迟到 Stop；缺少可靠取消信号时不推测 cancelled。
工具被拒绝、工具失败、会话退出和整轮失败不能混为同一终态。

## 4. 安装、隐私与失败隔离

安装合并现有配置，仅管理本来源的 Saki 条目；幂等安装、卸载和重新安装保留其他 hooks、
permissions、env。备份仅存原配置目录且为私有文件。用户级与项目级推荐二选一，
指南须解释重复安装和客户端重载要求。检查命令只报告安全状态，不打印配置或认证信息。

观察 hook 不参与 Claude Code 决策：stdout 为空、正常错误路径 exit 0，不输出批准、阻断或
上下文注入 JSON。输入上限 64 KiB、handler deadline 1 秒、IPC 上限 4 KiB、发送等待
不超过 50 ms；不等待设备扫描、ACK、连接或刷盘。外层 command timeout 沿用 2 秒兜底。
Host 未启动、设备离线、身份文件损坏、非法输入时应快速退出且不影响 Agent 继续执行。

继承已与实现对齐的 [0.4 隐私契约](../0.4.0/SPEC.md#2-身份来源和隐私)：仅在新请求中
优先处理 task_title，回退 prompt，提取不超过 48 字符/96 UTF-8 B 的 goal。goal 经过本地
IPC、0600 检查点和设备 task.title；无有效新目标时保留原目标，首次无目标才回退来源加短 ID。
工具、结束、resume 和已识别的“继续”不覆盖目标。

HMAC 只匿名化身份。规则过滤不是完全匿名化，短请求可能完整成为标题，姓名、邮箱、
相对路径及未识别凭据仍可能保留。原始 hook 对象和独立完整 prompt 字段不落盘或转发；
不读取 transcript，不从 cwd、工具参数/结果或回复生成标题。安装的 hook 静默，常规同步
日志不输出 goal；显式 `hook --stdout` 诊断含 goal，可能含用户原文片段。
本版保持该策略，回归测试验证已声明规则和数据流，不承诺识别全部敏感内容。

## 5. 兼容性与发布门槛

- 0.4.5 Host 对 0.4 固件沿用 multi-session；对 0.3 固件降级为同一最新提交单任务。
  0.4 Host 对 0.4.5 固件继续沿用既有协议；不得要求设备理解 Claude 原始事件。
- Claude Code 2.1.270 仅有历史基本生命周期证据，不是已确认的最低支持版本。
  发布前记录受测版本、配置接受情况、事件覆盖和限制；不能笼统声称支持所有版本。
- 必须通过离线回归，以及真实 Claude 单会话、多会话、批准、提问、工具失败和异常结束
  的相称验证；难以安全触发的场景明确列为限制，不能用合成测试冒充真实通过。
- 真实 2 Codex + 2 Claude Code 验证独立状态、耗时、焦点和恢复；关闭继承的 0.4/0.3
  发布阻塞项。设备画面、触摸和断线覆盖层须真机确认。
- 规划阶段不改运行版本号。进入发布时 Host 与固件正式版本一致，按现有流程构建和封包。

## 6. 范围冻结与完成定义

本版交付为已有 Claude 接入的可验证完善：事件/版本覆盖表、必要的 Host 修复与回归、
可恢复的安装流程、真实来源验收及安装排障指南。不预设增加新功能才能完成版本；
已有行为符合规格且证据充分的项目直接复用，只修复确认存在的差距。

批准、提问、工具失败必须有真实可控场景验证；StopFailure 若不能安全触发真实 API 异常，
须提供合成覆盖并在兼容表明确“未真实验证”，不得声称异常结束全场景实测通过。
没有可靠事件的取消、通知和跨轮乱序属于已知限制，不能用推测状态通过验收。
配置/静默退出、身份隔离、状态错误和声明的数据边界回归失败均为发布阻塞；
继承的硬件门槛仍按 0.4 TASKS 关闭。计划完成与版本验收完成分别记录。

## 7. 未开始会话的显示筛选

本节覆盖 0.4 的新建 idle 显示和无提交记录时的主项选择策略，两种来源一致。
仅 SessionStart 登记、没有有效提交且仍为 idle 的记录不进入主屏/侧栏；SessionEnd、
重复 SessionStart 或检查点恢复不会让这种记录占屏。Host 仍跟踪它，沿用容量和 TTL。

有效请求使记录进入显示并成为最新提交主项；已登记会话即使漏掉请求，后续可信工具、
等待或终态也可使其进入显示，但不抢有提交记录的主项。未知身份的工具/结束事件仍拒收，
不绕过既有防复活规则。筛选条件为 submitted_order > 0 或当前状态不是 idle。

有提交记录时仍选择最新有效提交；全无提交记录（包括旧检查点）时按状态注意优先级选择，
同级按 rank_since、脱敏 ID 稳定排序。侧栏顺序调整为等待批准 → 等待输入 → 失败 → 活动
→ completed/cancelled → idle。Stop 的 60 秒 TTL 保持不变，新开空闲客户端不会挤走它。

没有候选时发送空 sessions，设备沿用“暂无会话”，旧固件显示 idle。
协议 total 仍表示 Host 跟踪总数，包含未开始记录，因此可出现 0/N；不改字段含义、schema、
固件或计数协议。hidden_attention 仍仅计投影外等待/失败项，未开始记录不计注意事项。
