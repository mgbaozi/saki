# Saki 0.4.5 工程实施记录

> 状态：已发布并冻结；以下保留当时的实施设计，不是当前待办清单。
> [SPEC](./SPEC.md) · [TASKS](./TASKS.md)

## 1. 复用结构

```text
Claude Code command hook
  → 现有 wrapper / CLI hook → Claude adapter 与白名单脱敏
  → SourceEvent / 本地 IPC → SessionRegistry
  → 现有投影 / USB 或 BLE → 设备完整快照
```

继续使用 `host/src/saki_host/adapters/claude_code.py`、公共 adapter、`hooks_config.py`、
`identity.py`、`sessions.py` 和现有 CLI；不另起服务或为 Claude 分叉固件。
安装器与 adapter 的来源事件清单必须一致，未知字段不能隐式进入 SourceEvent。

## 2. 实施顺序

1. 核对官方事件输入与实际受测版本。以脱敏合成 fixture 固定必需字段、未知字段、缺失身份、
   未知工具、子会话和迟到事件；先明确客户端能力，再确定支持版本表。
2. 对现有映射做差距修复，重点覆盖批准后继续/拒绝、提问后继续、工具失败后继续、
   Stop 后继续及异常结束。保留现有 TTL、焦点和因果顺序限制，不增加猜测性终态。
3. 检查安装/重装/卸载、配置冲突、项目路径与解释器路径含空格、配置损坏、禁用 hooks、
   双作用域安装和 wrapper 失效。尽量复用现有安全诊断字段；新增诊断不得暴露配置内容。
4. 继承已校准的 0.4 标题隐私契约，复用现有测试并补齐 Claude 来源覆盖，测试规则命中的敏感行、路径、凭据、超长及多字节文本；
   检查本地 IPC、检查点和设备输出，而非只测试单个脱敏函数。
5. 原计划在离线测试后执行真实客户端/API 与真机矩阵；发布时未执行的完整真机部分现已统一
   迁入 1.0 发布前门槛，不再作为 0.4.5 待办。

## 3. 验证方式

常规入口为 `scripts/check.zsh`；新增测试集中扩展 `host/tests/test_sources.py` 等已有用例。
安装测试仅使用临时配置和状态目录，不修改开发者的真实 Claude 设置。

复用 `scripts/test-claude-hooks.py` 的显式真实 API probe，普通检查不调用模型。
当前入口的预算与时间限制保持有效；扩展交互批准/提问场景时优先人工可控验证，
不要用自动批准去模拟等待批准。记录客户端版本、场景、事件类别/计数和结果，
不保存原始 payload、模型输出或真实身份。

真机投影入口为 `scripts/test-device-sessions.py`，合成协议测试与真实来源测试分别记录。
该入口及独占 CDC 规则继续供 1.0 集中真机矩阵使用：操作前停止常驻 Host，结束后恢复，
不同时运行第二个 Host。

## 4. 兼容与交付

本版预计以 Host 和文档改动为主，协议保持不变。若实施发现必须修改协议或状态语义，
先更新本版规格，同时检查 schema、fixtures、两端模型/测试和兼容说明。
发布材料提供受测 Claude 版本表、安装/卸载说明、已知限制及安全验证摘要。
历史发布证据见 TASKS；后续真机门槛只在 1.0 路线图和对应版本任务中维护。

## 5. 原计划工作包与依赖

| 顺序 | 工作包 / 主要位置 | 完成条件 |
| --- | --- | --- |
| M1 | H0，adapter 与 hooks_config | 固定受测版本及安装事件清单；逐事件标注合成/真实/未覆盖，不把历史版本当最低版本 |
| M2 | H1/H2，adapter、sessions 与 test_sources | 生命周期和来源隔离矩阵通过；确认缺陷才改代码；未支持语义维持忽略策略 |
| M3 | H3/H5，安装器、CLI 与 wrapper 测试 | 临时目录安装/重装/卸载往返通过，其他配置保留；异常输入/服务缺失不阻断客户端 |
| M4 | H4，task_goal、IPC、checkpoint、display 测试 | Claude 与 Codex 均通过既有规则、标题保留和数据流回归；文档明确规则局限 |
| M5 | V，现有来源 probe 与真机入口 | 离线通过后完成真实来源与兼容矩阵，证据仅保留版本、类别、计数及安全摘要 |
| M6 | R，版本元数据、用户指南与发布材料 | 版本一致并生成候选包，再按授权执行发布动作 |

M1 先确定客户端支持范围；M2–M4 的验证结果共同作为 M5 的前置。不会因本机安装就绪
跳过临时配置回归，也不会为复验卸载用户正在使用的 hooks。已有安装证据见 TASKS。
客户端不接受某个事件名时，先在临时配置复现并记录支持边界；不静默漏装后报告完整支持。
若需要按版本生成不同清单，先更新 SPEC 和用户指南再实现，避免引入未定义的自动降级。

## 6. 空闲会话筛选实现

SessionRegistry.visible 在主项选择前剔除 submitted_order=0 且 state=idle 的记录，
使用现有持久化字段，因此无需检查点迁移。旧记录缺 submitted_order 时，非 idle 仍可显示。
focus 和新设备 projection 共用 visible，旧设备同步得到同样的筛选结果。
_RANK 将 completed/cancelled 放到 idle 前；没有有效提交时复用注意优先级选主项。
仅 Host 显示策略变化，不改变来源状态映射、会话准入、TTL 或线协议计数。

回归覆盖两来源对称场景、60 秒完成边界、空投影 schema、后续提交、漏请求后的可信活动、
resume、关闭及旧检查点恢复。设备现有空屏文案为“暂无会话”，不在本次修改中改为“暂无任务”。
