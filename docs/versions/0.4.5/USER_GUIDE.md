# Saki 0.4.5 Claude Code 用户指南草案

> 规划文档，0.4.5 尚未发布。以下入口复用现有 0.4 开发版能力；支持版本及完整验收待补齐。

## 接入流程

1. 按根目录 README 准备 Host，按 [0.4 用户指南](../0.4.0/USER_GUIDE.md) 启动服务与连接设备。
2. 使用现有 `saki-host hooks install --source claude_code` 安装，并用同一入口的 `check`
   检查配置、wrapper 与身份密钥。完整仓库命令见上述指南，不需要另外配置 Saki API key。
3. 用户级配置与显式项目级配置选择一种；重开 Claude Code 会话后验证新请求、工具和结束。
4. 用 `uninstall --source claude_code` 卸载本来源的 Saki 条目；项目级操作须始终使用同一
   `--settings` 路径。其他 hooks 和用户设置应保留。

正常状态显示、独立计时、主屏/侧栏、记录清理及 USB/BLE 使用沿用 0.4 指南。
批准与提问须回 Claude Code 操作，Saki 仅显示状态。

## 排障顺序

- 无状态：先看 hook 检查结果，再确认客户端加载配置和 Host 服务状态，最后检查设备连接。
- 跨项目不生效：确认安装作用域及 wrapper 路径；移动仓库或解释器后重新安装。
- 重复更新：检查是否同时在用户级和项目级安装；仅清理 Saki 自己的重复条目。
- 等待/过期不消失：检查客户端是否实际产生后续事件；没有可信信号时不会猜测完成或取消。

不要为排障分享完整 settings、hook payload、transcript 或身份密钥。
`check` 的安装就绪不等于真实事件已抵达设备。发布前补充受测客户端版本和实际限制；
当前已知的 Notification、取消、跨轮迟到及未覆盖输入等待边界见 [SPEC](./SPEC.md)。

## 标题与隐私

沿用 [0.4 标题说明](../0.4.0/USER_GUIDE.md#恢复与限制)：从新请求的 task_title 或 prompt
按本地规则提取短句，最多 48 字符/96 UTF-8 B，发送给 Host、私有检查点和设备。
短请求可能原样显示；规则不能过滤所有敏感信息。无有效新目标时保留原目标，首次无目标
显示来源和短 ID。安装的 hook 静默，手动 `hook --stdout` 的诊断结果则包含派生目标。

首次确认可在新开的 Claude Code 会话提交一个不含敏感内容的简单任务，观察屏幕是否出现
Claude 来源、短标题和结束状态。安装检查成功但屏幕未更新时，按上述排障顺序定位；
不能仅根据静态配置检查判断真实接入成功。

## 未开始的会话

仅打开 Claude Code 或 Codex 不再产生占屏的空闲卡片；首次提交请求后才成为主屏。
已登记会话漏掉请求时，后续可信工具/等待事件也可进入显示，但不抢已有提交的主屏。
已完成任务仍保留 60 秒；之后若只剩未开始的会话，屏幕显示“暂无会话”。
Host 仍跟踪这些会话，底栏总数可能大于实际显示数；它们不会计入隐藏注意事项。
