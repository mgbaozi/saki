# Saki 路线图

本文件只维护版本方向、依赖关系和尚未进入版本规格的工作。版本内功能、任务和验证证据分别以
对应的 `SPEC.md`、`IMPLEMENTATION.md` 和 `TASKS.md` 为准，不在路线图重复当前进度。

版本一经发布即冻结：没有在该版本执行的验证不继续作为其“待关闭验收”，而是明确迁入后续
里程碑。0.x 期间积累的完整真机矩阵统一作为 1.0 发布前门槛。

## 版本方向

| 里程碑 | 主题 | 核心结果 | 文档 |
| --- | --- | --- | --- |
| 0.3.0 基线 | 安全 BLE fallback | USB 优先、BLE 绑定与双传输仲裁；已并入 0.4.5 | [版本文档](./versions/0.3.0/SPEC.md) |
| 0.4.0 基线 | 多 Agent / 多 Session | Codex / Claude Code 多任务页面与完整集合协议；未单独发布，已并入 0.4.5 | [版本文档](./versions/0.4.0/SPEC.md) |
| 0.4.5 | 首个多来源稳定版 | 多来源、多 Session、安装流程与空闲会话筛选 | [发布说明](./releases/0.4.5.md) |
| 0.5.0 | 可扩展 Agent 接入与视觉体验 | 注册表式 adapter、通用来源标签、图片化状态与可控趣味文案 | [发布说明](./releases/0.5.0.md) |
| 1.0 | 稳定硬件基线 | 汇总并关闭完整真机、交互、传输恢复与资源门槛 | 本文件“1.0 发布前真机门槛” |
| 1.1+ 候选 | Wi-Fi | 局域网传输、配网与三传输仲裁 | 尚未排期 |

0.3 与 0.4 是形成 0.4.5 的历史开发基线，不再作为平行在制版本。0.5 以 0.4.5 为唯一发布
基线；1.0 汇总 0.x 延后的真机矩阵，不反向把已发布版本标记为“验收中”。

## 0.5.0：可扩展 Agent 接入与视觉体验

0.5 已正式发布；冻结的[版本规格](./versions/0.5.0/SPEC.md)、
[工程实施](./versions/0.5.0/IMPLEMENTATION.md)、[任务记录](./versions/0.5.0/TASKS.md)、
[用户指南](./versions/0.5.0/USER_GUIDE.md)和[发布说明](./releases/0.5.0.md)保留实际范围与证据。

本版先把 Codex / Claude Code 的来源分支收敛为显式 `AdapterSpec` 注册表，并通过能力协商让
新固件接受有界通用来源标签；旧固件对未来来源安全降级为 `legacy / Agent`。随后在同一通用
语义状态上完成图片化状态标识、页面细化和可关闭的轻量趣味文案。

Host 32 项、设备 4 项的容量限制不随 Agent 种类变化。0.5 建立扩展机制，但不承诺接入第三个
Agent，也不提供动态插件加载、在线主题、Wi-Fi、OTA 或远程批准。0.5 的发布门槛是离线契约、
Host 测试、dev/release/Unity 构建、资源许可与可复现生成；完整真机验收统一进入 1.0 门槛。

## 1.0 发布前真机门槛

1.0 候选产生后，在用户明确允许且目标设备已连接时执行一次统一矩阵。测试使用当次 1.0
release candidate，不回头为每个 0.x 版本分别补验收。

### 设备与显示

- 在 ATK-DNESP32S3B3 / ESP32S3 BOX3 的 320×240 真机上覆盖九种状态、常用活动类型、
  1/2/4 Session、中文/英文/最大边界文本和通用 Agent 来源标签。
- 验证主屏/侧栏选择、详情切换、15 秒返回、暗屏首次触摸唤醒、断线覆盖层、BLE 配对/K2
  提示以及等待批准/等待输入/失败页面。
- 检查状态更新、计时和重复完整快照不造成白屏、闪烁、错位、错误动画重播或触摸失效。
- 验证资源缺失与受控低内存路径回退到完整可读的文字界面。

### 来源与恢复

- 使用真实 Codex / Claude Code 各至少两个 Session，确认身份、标题、状态、耗时和主屏焦点
  互不串写；记录受测客户端版本和实际事件覆盖。
- 验证 Host 重启、Mac 服务重启、设备复位、USB 热插拔和检查点恢复；恢复状态必须冻结并在
  可信新事件后继续。
- 验证 1.0 Host/firmware、上一稳定 Host→1.0 firmware、1.0 Host→上一稳定 firmware 的兼容
  行为；未来来源在旧固件上安全降级，不得拒绝整组 Session。

### USB / BLE 与资源

- 覆盖 USB、已绑定 BLE、USB→BLE、BLE→USB、连接丢失和重连；高优先级链路完成握手和完整
  Session 同步后才能接管，不出现空列表或旧状态回退。
- 记录 release 固件大小、分区余量、稳定/最低 internal heap、PSRAM、关键任务最低 stack、
  BLE 诊断计数和连续页面切换趋势；不得出现持续内存下降、队列卡死或 watchdog reset。
- Unity 真机测试覆盖显示固件后，记录结果并刷回 1.0 release candidate，恢复 Host 服务。

### 证据与退出条件

- 只保留受测版本、场景、结果、资源摘要和已知限制，不提交真实设备 ID、原始 hook、完整日志、
  串口捕获、截图或本机路径。
- 任一阻塞项必须在 1.0 `TASKS.md` 中修复、降级为明确非目标，或由用户决定延期；不得让
  1.0 发布后仍显示为该版本“验收中”。
- 24 小时/10,000 次 soak、Mac 睡眠/唤醒和光学延迟仍是可选工程表征；未执行时只记录为
  未执行，不作为 1.0 发布后持续悬挂的任务。

## Wi-Fi 候选（1.1 或以后）

Wi-Fi 只有在重新确认其价值高于配网、安全、支持和验证成本后才建立版本规格，当前不构成
0.5 或 1.0 承诺。候选设计输入如下：

- 通过 USB 或 BLE 配置，不硬编码 SSID/密码；凭据在 NVS 中有界存储并可单独清除。
- 候选服务使用 mDNS 和有界 TCP transport，复用同一协议 parser，不复制状态模型。
- 无有效配对令牌不接受状态更新；正式规格必须先冻结可信局域网、访客网络、恶意同网设备和
  TLS/证书轮换威胁模型。
- 三传输候选优先级为 `USB > BLE > Wi-Fi`，接管必须沿用完整集合与原子仲裁语义。

## 未排期方向

- 多套可配置主题、更完整的亮度和空闲策略。
- 安全的有限交互，例如提醒用户处理批准，但不代替用户批准高风险操作。
- OTA 更新、诊断页和更完整的设备设置页。
- 手机端、浏览器端或跨平台 Host。
