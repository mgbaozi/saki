# Saki 路线图

本文件记录版本方向及尚未进入版本规格的工作；已迁入版本目录的内容只保留摘要与链接。
当前实现和验收状态以对应版本的 `SPEC.md`、`IMPLEMENTATION.md` 和 `TASKS.md` 为准，
路线图中的版本号与条目不代表已经实现。

安全 BLE fallback 已迁入 [0.3.0 规格](./versions/0.3.0/SPEC.md)、
[工程设计](./versions/0.3.0/IMPLEMENTATION.md)和[任务清单](./versions/0.3.0/TASKS.md)。
0.3.0 发布基线关闭后，近期优先完善多任务可见性和设备表现力；Wi-Fi 暂不作为近期主线。

## 版本顺序

| 版本 | 主题 | 核心结果 | 当前状态 |
| --- | --- | --- | --- |
| 0.3.0 | 安全 BLE fallback | USB 优先、BLE 绑定与双传输仲裁 | 实现与验收中 |
| 0.4.0 | 多 Agent / 多 Session | 同时展示 Codex / Claude Code 的多个独立任务 | 核心实现与离线验证通过，真机验收中 |
| 0.4.5 | Claude Code hook 支持完善 | 复用已有接入，补齐生命周期、安装排障与来源验收 | 实施中，空闲会话筛选已完成 |
| 0.5.0 | 视觉与趣味体验 | 图片化状态标识、视觉细化和可控的趣味文案 | 规划 |
| 0.6.0+ | Wi-Fi 候选 | 局域网传输、配网与三传输仲裁 | 低优先级，未承诺版本 |

依赖顺序：0.4 以稳定的 0.3 transport 为基础；0.4.5 完善已有 Claude Code hook 支持；
0.5 复用 0.4 的多 Session 页面结构；Wi-Fi
只有在重新确认需求和安全投入后才进入正式版本规格。

## 0.4.0：多 Agent / 多 Session 状态展示

本版本已展开为[版本规格](./versions/0.4.0/SPEC.md)、
[工程设计](./versions/0.4.0/IMPLEMENTATION.md)和
[实施任务与验证计划](./versions/0.4.0/TASKS.md)，详细契约和任务只在版本目录维护。
当前开发版本为 0.4.0-dev；核心代码、离线检查和构建已通过，真机混合并发及资源验收待完成。

多 Agent 指 Codex、Claude Code 等不同 coding agent 产品；多 Session 指它们各自的多个
任务/对话。0.4 必须新增 Claude Code adapter 与 hook 配置流程，代表场景为 2 个 Codex +
2 个 Claude Code Session 同时显示，来源名称清晰、状态/耗时独立，USB/BLE 切换后原子恢复。
同一 Host 统一收集和脱敏，两种来源共用协议；单 Mac 和 BLE 安全边界保持不变。
主屏展示最近提交新请求的 Session，其余任务在侧栏用状态色和小字展示，替代整屏列表。

发布前仍须关闭来源实测、稳定 transport 基线和真机容量/交互决策门。线协议已选定
capability 协商的 v1 单帧完整集合，Claude Code 单会话真实 API probe 已通过；实际覆盖与
剩余任务统一记录在 [0.4 TASKS](./versions/0.4.0/TASKS.md)。

## 0.5.0：视觉与趣味体验

### 版本目标

在 0.4 信息架构稳定后，提高状态辨识度和设备个性：用小型图片资源替代主要纯色占位块，
增加节制、可关闭且不影响关键信息的趣味梗文案。视觉资源仍由设备端根据语义状态映射，
Host 和协议不为某个角色、品牌或主题分叉。

### M5.1 图片资源与视觉语言

- 为 Agent 状态、活动类型和通用 Agent 身份建立设备端图片映射；未知类型始终有中性 fallback。
- 优先使用适合 320×240 的小尺寸静态图或轻量帧动画，明确分辨率、色深、透明度、缓存和
  PSRAM/Flash 预算。
- 建立可复现的素材转换脚本和来源清单；生成的 LVGL 资源不手工修改，原创与第三方素材都保留
  许可证和版权声明。
- 图片只强化识别，不替代文字状态、进度和等待批准等关键语义；不能仅靠颜色区分状态。
- 第一版只维护一套一致视觉语言，不同时建设主题商店、在线下载或用户上传素材。

### M5.2 页面与动效优化

- 用图片 logo/图标替换总览卡片和详情页中的主要纯色块，同时统一圆角、间距、层级和状态色。
- 优化 0.4 总览与详情之间的转场、选中态和注意提示；状态更新不得导致整屏刷新或重复播放终态
  动画。
- 针对图片加载失败、资源缺失和低内存提供无崩溃的文字/矢量 fallback。
- 保持离线、BLE 配对、K2 提示和批准等待页面的严肃可读性，不让装饰遮挡操作信息。

### M5.3 趣味梗文案

- 在设备端维护按 `state`、`activity.kind` 和多 Session 状态分类的短文案库，例如编译、等待、
  完成和失败时的轻量提示；Host 不发送为某个角色定制的梗文本。
- 一次语义状态停留期间固定一条文案，只在真实状态变化或新 Session 焦点切换时选择，避免每帧
  随机造成闪烁。
- 核心状态名称和真实摘要始终优先；`waiting_approval`、`waiting_user`、`failed` 等场景的梗文案
  只能作为副标题，不能弱化风险或误导用户。
- 文案需短、无攻击性、无隐私内容，并检查中英文边界和 CJK 字体覆盖。
- 提供“关闭 / 轻量”本地设置并持久化到设备配置；设置不能改变协议状态或 Host 行为。

### M5.4 验收门槛

- 九种状态、常用活动类型和 0.4 的 1/2/4 Session 页面都有一致图片映射和 fallback。
- 真机检查中英文边界、触摸、暗屏唤醒、离线覆盖、BLE overlay 和全部转场，无白屏或闪烁。
- 连续切换图片与文案不造成持续内存下降、UI 卡死或任务栈低于安全线。
- release app 仍保留至少 20% 分区余量，素材来源、哈希、生成方式和许可证可审计。
- 趣味文案关闭后界面仍完整；开启后不改变 ACK、状态时序或 transport 行为。

### 非目标

- 不由 Host 或云端动态生成图片、角色台词或个性化内容。
- 不引入在线素材市场、账号、遥测或内容推荐。
- 不为单个角色复制协议、Host service 或整套页面逻辑。
- 不把 Wi-Fi、OTA 或设备远程管理混入视觉版本。

## Wi-Fi fallback（低优先级，候选 0.6.0 或以后）

Wi-Fi 不再占用 0.4/0.5 版本号。只有用户重新确认其价值高于配网、安全、支持和验证成本后，
才创建对应版本的 `SPEC.md`、`IMPLEMENTATION.md` 和 `TASKS.md`。以下条目保留为候选设计输入，
不是已经排期的承诺。

### W0.1 配网与凭据存储

- 通过 USB 或 BLE 配置，不硬编码 SSID 或密码。
- 在 NVS 中安全存储并提供只清 Wi-Fi 凭据的流程。
- 明确首次配网、换网、无网和错误凭据的 320×240 交互。

### W0.2 mDNS 和 TCP transport

- 候选服务使用 `_saki-agent._tcp.local` 和端口 8765，最终值由正式规格确认。
- 复用同一有界协议 parser，不为 Wi-Fi 复制状态模型。
- 多个网络连接并存时只允许一个经过授权的 Host 控制 UI。

### W0.3 配对令牌和 TLS 决策

- 无有效令牌不接受状态更新，凭据和原始报文不进入日志。
- 明确可信局域网、访客网络和恶意同网设备的威胁模型。
- 在实施前决定是否强制 TLS，以及证书、密钥轮换和恢复出厂后的处理方式。

### W0.4 三传输仲裁

- 复用 0.3 的 transport manager 和 0.4 的多 Session 同步语义。
- 运行时优先级暂定 `USB > BLE > Wi-Fi`，但须在 Wi-Fi 正式规格中根据功耗、延迟和安全重新确认。
- 新增 USB↔Wi-Fi、BLE↔Wi-Fi 切换矩阵，并完整回归 USB↔BLE。
- 高优先级链路完成 hello 和全量 Session 同步后才能原子接管，不能出现空列表或旧 Session 回退。

## 增强功能（未排期）

- 可配置主题、亮度和空闲策略。
- 安全的有限交互，例如提醒用户处理批准，但不代替用户批准高风险操作。
- OTA 更新、诊断页和更完整的设备设置页。
- 手机端、浏览器端或跨平台 Host。

## 可选工程验证（不阻塞当前版本发布）

- 24 小时且至少 10,000 次状态更新的长时间 soak。
- USB 模式下的 Mac 睡眠/唤醒恢复矩阵。
- 使用高速摄影或光学探头测量 Agent hook 到 LCD 最后像素可见变化的端到端延迟。
